# Публикация PA–2004 на GitHub Pages

Готовые 140 страниц и все ресурсы находятся в `dist/`. Сайт статический: сервер, Node.js, API-ключи и сборка не нужны. 3D, карусели, переключение языка, изображения и контакты поддерживаются GitHub Pages. YouTube и внешние ссылки требуют интернета; 3D требует WebGL.

## Загрузка и получение ссылки

1. Откройте репозиторий `ritter-pro/Portfolio_PA` или создайте новый публичный репозиторий. Если файлы уже есть, сохраните их копию и объедините изменения.
2. Распакуйте архив. Загрузите его содержимое в корень репозитория: папки `dist`, `.github`, скрипт `prepare-pages.py` и документы. Папка `.github` может быть скрыта в файловом менеджере. Сам ZIP загружать в репозиторий не нужно: GitHub должен видеть файлы внутри.
3. Основная ветка — `main`. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. В **Actions → Publish portfolio to GitHub Pages → Run workflow** запустите публикацию. Последующие изменения в `main` публикуются автоматически.
5. Дождитесь зелёного статуса. Рабочая ссылка появится в **Settings → Pages** и в успешном запуске Actions. Для `Portfolio_PA` стандартный адрес ожидается `https://ritter-pro.github.io/Portfolio_PA/`. До успешного запуска это ожидаемый адрес, а не подтверждённая публикация.

## Через Git — удобнее для большого количества файлов

Если репозиторий пустой, откройте терминал внутри распакованной папки:

```bash
git init -b main
git add .
git commit -m "Publish final PA-2004 portfolio"
git remote add origin https://github.com/ritter-pro/Portfolio_PA.git
git push -u origin main
```

Затем включите Pages по пункту 3. При запросе входа используйте обычную авторизацию GitHub. Не помещайте токены в файлы сайта.

Если репозиторий уже содержит коммиты, сначала клонируйте его, скопируйте в него содержимое архива и выполните `git add .`, `git commit`, `git push`. Не используйте force push.

## Локальный просмотр и правки

```bash
python -m http.server 8000 --directory dist
```

Откройте `http://localhost:8000/`. Открытие HTML двойным щелчком не подходит для 3D, которому нужен HTTP.

Пути относительные: работают корень домена, `/Portfolio_PA/` и английские страницы. `prepare-pages.py` подставляет настоящий адрес публикации в метаданные. GitHub Pages даёт дополнительный адрес хостинга; существующий опубликованный сайт уже работает.

Для обновления готового сайта достаточно менять файлы в `dist/` и отправлять изменения в `main`. Полноразмерные изображения сохранены для увеличенного просмотра; облегчённые находятся в `assets/responsive`. Книжные мокапы используют заранее подготовленные `assets/print-ready`, не обрабатывают PNG на устройстве посетителя.

Официальная документация: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages
